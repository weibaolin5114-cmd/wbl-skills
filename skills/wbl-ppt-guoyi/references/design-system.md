# 品牌粉设计系统（HTML / SVG / PPTX 共用）

> 视觉基准：`./gold-sample/guoyi-html-deck-v2.html`
> 设计取向：极简、大留白、冷灰 + 一点粉、平面色块、左对齐

---

## 0. 规则分级（先读这一节）

本文件里的规则分三级，**按级别区别对待**：

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| **硬约束** | 违反会直接出错（乱码、LOGO 空白、文件打不开）或破坏品牌识别 | 必须遵守，无例外 |
| **设计原则** | 决定"好不好看"的判断依据 | 结合页面情况判断，允许合理偏离 |
| **参考区间** | 经验数值，不是标准答案 | 可偏离；偏离时在交付说明里讲一句理由 |

写页面时**不要逐条对照参考区间**。顺序是：先满足硬约束 → 再用原则做判断 → 参考区间只在没有想法时当起点。

原则和参考区间冲突时，**以原则为准**。

## 1. 硬约束（必须遵守）

| # | 约束 | 原因 |
|---|------|------|
| H1 | 全程禁用 Emoji（含 ✅❌⭐🚀）。状态用文字或几何符号（● ■ 1 2 3） | 品牌规范 |
| H2 | 画布固定 **1280 × 720**（16:9） | 投屏比例 |
| H3 | PPTX 通道 SVG **禁用**：`mask`、`<style>`、`class`、`foreignObject`、`symbol+use`、`textPath`、动画与脚本 | 转换器不支持，会丢元素 |
| H4 | LOGO 固定写 `<image href="../images/logo.png" x="1041" y="44" width="220" height="31" preserveAspectRatio="xMidYMid meet"/>`，路径与坐标不得改、不得嵌套包装 | 路径错则 LOGO 空白，尺寸错则走形 |
| H5 | 字体族固定：中文 **Microsoft YaHei**、数字 **Arial**、URL/代码 **Consolas**。不得混入第三方字体、不用中文名「微软雅黑」 | 换字体或中文名会走形/方块 |
| H6 | `#CF2154` 是**全文档唯一彩色**，不得引入第二个彩色（含状态色） | 品牌单一色识别 |
| H7 | 正文可读下限 **13px**；已知投屏场合（大会场、后排远距离）下限 **15px** | 低于此不可读 |
| H8 | SVG 中 `& < > "` 必须用 XML 实体转义 | 否则文件解析失败 |
| H9 | 交付 PPTX 必须**全原生可编辑**：文字是文本框、图形是形状/图表/表格；`<image>` 只允许 logo 与照片素材，正文/表格/图表不得用图承载 | 用户要二次编辑、改数字 |
| H10 | **禁止图片化导出**：不得用 `--only legacy` 或 `--svg-snapshot` 产物交付；导出后必须跑 `scripts/pptx_editability_check.py` 且结论为"通过" | legacy 通道把整页渲染成图片 |

硬约束只有这 10 条。**其余全部是可以判断的。**

## 2. 设计令牌

### 2.1 色板

| Token | 色值 | 用途 |
|-------|------|------|
| `primary` | `#CF2154` | 序号、关键词、章节短线、对比强调、少量标签——**只做强调** |
| `primary-soft` | `#FCE8EE` | 极少用：只在"双栏对比"里给需要突出的那一栏做底 |
| `primary-wash` | `#FDEEF3` | 章节页大号水印数字、封面几何圆 |
| `ink` | `#212121` | 标题、关键文案 |
| `text` | `#4B5563` | 正文、卡片内容、表格正文 |
| `text-3` | `#6B7280` | 注释、来源、页码、次要标注 |
| `surface` | `#F7F8FA` | **卡片/色块默认底色**（替代原来的白底+描边） |
| `surface-2` | `#EEF0F3` | 表头底、次级色块 |
| `surface-3` | `#E3E6EB` | 需要第三层的块（如轨道、分隔带） |
| `bg` | `#FFFFFF` | 页面底色 |

**粉色的角色分工（最重要的一条）**

`#CF2154` 是**强调色**，不是结构色。判断方法：

> 把页面上所有粉色拿掉，页面结构是否依然清晰、能读懂？
> 如果变得不可读——说明粉色用错位置了，它被当成了结构。

粉色**可以**出现在：序号、目录编号、章节短线、章节水印、需要突出的关键词、对比条。
粉色**不要**出现在：页面标题字、容器描边、表格表头底、全宽顶线、正文。

**同一层级的小标题必须同色同重。** 灰底块 / 卡片内部的小标题统一用 `ink`（#212121）加粗；粉色只给序号、关键词与结语强调句。典型错误是"这一页的小标题黑、那一页的粉"——层级相同却颜色不同，读者会误判层级，返工时也找不到规律。例外：模板类占位字段标签（如 `# 角色` `# 不记`）属于关键词而非标题，可保留粉色。

### 2.2 版心

| 项 | 值 |
|----|-----|
| 画布 | 1280 × 720 |
| 左右边距 | 80px（内容区 x=80 → x=1200，宽 1120px） |
| 内容页起始基线 | 标题基线 y≈96px |
| 页脚基线 | y≈676px |

左右边距 HTML 与 SVG 两通道**保持一致**，不再各用一套。

## 3. 字阶（5 档）

不是"必须用这 5 个字号"，而是**层级之间要拉得开**。字号全部挤在 16–24px 会让页面发扁。

| 档 | 用途 | 参考字号 | 字重 | 颜色 |
|----|------|----------|------|------|
| 1 | 封面主标题 | 40px | Bold | `ink` |
| 2 | 内容页标题 / 章节页标题 | 26px / 40px | Bold | `ink` |
| 3 | 小节标题、卡片标题 | 17–18px | Bold | `ink` |
| 4 | 正文、表格正文、结论条 | 14px | Regular | `text` |
| 5 | 明细、注释、来源、页码 | 13px | Regular | `text-3` |
| 装饰 | 目录编号 40px；章节水印 160px | — | Bold | `primary` / `primary-wash` |

**层级对比原则**：相邻两档字号差距太小就没有层级。宁可少用一档，也不要把 15/16/17 堆在一起。

### 3.1 关键信息强调

时间、比例、数量、级别、通道代号等，用 `primary` 加粗，**内联在句子里**：

- HTML：`<span class="num">2000</span>`
- SVG：`<tspan fill="#CF2154" font-weight="bold">2000</tspan>`

不要用绝对坐标把数字拆成孤立色块——会切断阅读。

## 4. 页眉与页脚

### 4.1 内容页（默认式样）

只有两样东西：

- **左对齐页面标题**：26px，`ink`，Bold，基线 y≈96px，从 x=80 起
- **右上角 LOGO**：固定 `<image href="../images/logo.png" x="1041" y="44" width="220" height="31" preserveAspectRatio="xMidYMid meet"/>`

**LOGO 落地机制**（三处保持一致，别再各写一套）：

| 环节 | 做法 |
|------|------|
| 源文件 | `templates/guoyi-fen/images/logo.png`（660×94 纯色占位，不含真实品牌标识） |
| 生成期 | 复制到 `<project>/images/logo.png`；SVG 里一律写 `../images/logo.png` |
| 导出前 | `finalize_svg.py` 自动把引用转 base64 写入 `svg_final/`，交付的 PPTX 不依赖外部文件 |
| HTML 通道 | 用几何品牌标，**不嵌 logo.png**（HTML 是沟通预览，不带品牌图） |

**不要**再加：顶部全出血粉线、左上角方块品牌标、标题下方全宽分隔线。这三样是"模板感"的主要来源。

### 4.2 章节页

**不放 LOGO、不放 PART 标签**（成品实测如此，别自作主张加回来）。

```
章节标题        ← 40px ink Bold，基线 y=264
[120×3px 粉短线，y=301]
要点 1/2/3/4    ← 18px text 纯文本行，不加卡片和边框；基线 y=391 起、行距 51
                        右侧：230px primary-wash 水印数字（x=799，基线 y=550）
```

水印数字很大、颜色极浅，落在右下区域（约 x 808–1021、y 383–550），**每个章节页都要有**，保持节奏一致。

### 4.3 页脚

默认**只保留右下角页码**：13px，`text-3`，不加顶部横线。

素材里有明确数据来源时，可在左下角加一行 12px `text-3` 来源标注；没有就不加。

正式汇报（页数 ≥15）建议保留页码——被追问时能定位。纯沟通预览可关闭。

### 4.4 封面 / 结尾

两页都**左对齐**：

- **封面**：标题 40px `ink` 基线 y=196 → 副标题 22px 基线 y=270（关键词可加 `<tspan fill="#CF2154">`）→ 320×3px 粉短线 y=344 → 作者 17px `text` 基线 y=539 → 单位/日期 14px `text-3` 基线 y=581，全部自 x=136 左对齐。装饰：左侧 5px 粉竖条（x=80, y=96, h=562, opacity .18）+ 右下双圆（r210 @ .03、r130 @ .02）
- **结尾**：22px `text` 行动句（基线 y=254）→ 64px `ink` 结语（基线 y=426）→ 320×3px 粉短线（y=472）。**极简：不要联系信息块、不要版权行、不要装饰圆**

## 5. 组件库（色块语言）

**总原则：容器用"填色"分层，不用"描边"分层。** 默认无边框、无阴影、无圆角。

| 组件 | 做法 |
|------|------|
| `panel` 面板 | `background: surface`，无边框、无阴影。需要区分层级就用 `surface` / `surface-2` / `surface-3` 三档深浅 |
| `lead` 结论条 | `background: surface`，14px，`ink` 正文 + 关键词 `primary`。**不用粉色底、不用左色条** |
| `eyebrow` 副标题 | 标题下方一行，13–14px `text-3` |
| `table` 表格 | **零边框**。表头 `surface-2` 底 + `ink` Bold；正文行 `surface` / `#FFFFFF` 隔行交替；无竖线 |
| `num-list` 编号列表 | 序号用 30px `primary` 数字，**独立成列**左右排列（不是 22px 圆序号） |
| `flow-strip` 流程条 | 等宽色块横排，`surface` 底 + `ink` 标签；需要突出的一格用 `primary-soft` 底 + `primary` 字 |
| `compare` 对比双栏 | 左栏 `surface` 底，右栏需要突出时用 `primary-soft` 底；中间可放 `primary` 箭头 |
| `icon-card` 图标卡 | `surface` 底，顶部品牌图标 + 名称 + 单位 + 数据（图标用真实品牌图，不用几何占位） |
| `bullets` 列表 | `ink` 或 `text` 正文，• 用 `text-3`，行距 1.55–1.7 |

**允许偏离**：如果页面需要一个上面没写的结构，就按"色块 + 左右对齐 + 5 档字阶"的原则自己搭，并在交付说明里写一句用了什么结构。禁止的是"每页都换一套新视觉语言"，不是"不许有新结构"。

## 6. 设计原则（做判断时用）

| # | 原则 | 判断方法 |
|---|------|----------|
| P1 | **每页一个视觉锚点** | 扫一眼，视线第一个落点是哪里？如果每块都想抢注意力，就说明没有锚点 |
| P2 | **粉色是强调，不是结构** | 见 2.1 的"拿掉粉色"测试 |
| P3 | **层级靠字号与明度对比** | 不要靠加粗、描边、底色堆强度 |
| P4 | **留白是设计手段** | 页尾允许留白 15–25%，不要为了填满而拉大字号或缩紧行距 |
| P5 | **先复用组件，再考虑新结构** | 组件能表达就不另起；确实需要新结构时按第 5 节的允许偏离处理 |
| P6 | **相邻页不要长得一样** | 连续几页都用同一种骨架会显机械。信息结构真的相同时才复用同一骨架 |
| P7 | **文字块按信息组拆分，不按行数硬切** | 拆分的依据是"这一段在讲什么"，不是"到第 3 行了" |
| P8 | **标题与内容之间要有层级间距** | 块内标题到首行内容的距离 ≈ 标题字号 × 2.2。距离太小（贴在一起）就没有层级；同一种块在不同页用不同距离，看起来像两个人做的 |
| P9 | **色块要贴住内容** | 内容在色块内**垂直居中**，上下留白相当、各不超过约 40px。内容只占上半部、下面空一半，是最扎眼的"没做完"观感，此时应收块高而不是硬撑 |

## 7. 参考区间（可偏离）

| 项 | 区间 | 说明 |
|----|------|------|
| 粉色引用密度 | 3–6 处/页（封面、章节页可到 7–8） | 用于自查，不是硬指标 |
| 左右边距 / 内容宽 | 80px / 1120px | 保持对称 |
| 色块内边距 | 14–20px | |
| 色块间距 | 12–16px | |
| 结论条、明细块长度 | 3–4 行 | 超过就考虑拆成信息组或拆页 |
| 留白 | 页尾 15–25% | |
| 表格行高 | 44–52px | 表中文字 13–14px |
| **块内标题 → 首行内容** | **标题字号 × 2.2** | 24→53 · 22.67→50 · 20→44。实测同一份 deck 里曾同时出现 21.7 与 60，必须收敛 |
| **块内多行正文行距** | **字号 × 1.65** | 17.33→28.6 · 18.67→30.8。低于 1.55 会显拥挤 |
| **块内列表条目间距** | **字号 × 2.0** | 单行条目之间。比正文行距再大一档，条目才分得开 |
| **色块内下留白** | **≤ 40px** | 内容不足就先缩块高，别靠加大字号或拉大行距来填 |

> 加粗的四项在多次实测中已收敛为固定值，**直接照用，不要逐页试数**。同一份 deck 内若同类块的间距不一致，视觉上会像两个人做的。

## 9. 交付前自检

**只查硬约束 + 三个观感问题。** 不要逐条对照参考区间。

硬约束：

1. 有没有 Emoji？ → 有就全删
2. 字号有没有低于 13px（投屏场合 15px）？
3. 除 `#CF2154` 外还有别的彩色吗？
4. PPTX 通道 LOGO 路径对不对？

观感三问：

5. **一眼能不能找到视觉锚点？**（P1）
6. **把粉色全部拿掉，页面还清楚吗？**（P2）
7. **字号层级拉得开吗？还是有 15/16/17 挤在一起？**（P3）

外加一条检查：相邻 3 页是否用了同一种骨架？是的话考虑换一种（P6）。

时间轴特有：若用了水平时间轴，连接线必须穿过圆点中心（结构为 `.tl-wrap > .timeline`，禁止给 `.timeline` 直接加 `flex:1`）。
