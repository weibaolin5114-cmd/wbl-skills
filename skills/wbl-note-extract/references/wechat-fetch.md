# 微信文章抓取判据

> 步骤 1~3 及步骤 8 取 `author` 时按需加载。所有数值均为实测，不是理论阈值。

## 一、图片真实地址

- 正文图片真实地址在 `data-src`，不在 `src`。按正文顺序抓全部 `<img ... data-src="...">`，再结合上下文段落逐张定位。
- 下载必须带请求头 `Referer: https://mp.weixin.qq.com/`，否则返回防盗链空图。
- 下载方式：`Invoke-WebRequest -Uri "<url>" -OutFile "$env:TEMP\note_img_N.png"`，或 Python `urllib`，等价。
- **笔记里若要嵌图片链接，只能从 `data-src` 原样复制**。禁止凭封面地址或其他文章地址拼接、猜测。教训：diagram-design 一文因凭封面拼链接，8 条图片地址全错，事后逐一替换。
- 写完必须回读文件，抽查链接是否与 `data-src` 一致。

## 二、信息型 / 装饰型判定

主判据是「位置 + 抽读」，不是尺寸：

- 夹在正文段落之间的图先全部列为候选。
- 直接剔除：带 `wx_lazy=1#imgIndex=` 的往期推荐与视频号缩略图；页首封面、作者肖像、页尾二维码、关注引导、分割线、表情包。
- 剩下候选按「是否含文字信息」抽读确认。

**`data-w` 只能当辅助线索**：随公众号模板浮动，实测 2026-09-16 三篇的正文图分别落在 1055、1184~2600、1080，与早期「正文图 3000–3600」的记录不符。用固定数值筛必然误伤。

**多张图字节数完全一致 = 同一张空白占位图**：实测 2026-09-17 一篇内 3 张 `w=1471` 均为 22665 字节的空白蓝色底图，直接判装饰型跳过，不要逐张 Read 浪费轮次。

**信息型图不必逐张读完**：正文文字已写清尺寸 / 步骤 / 结果的界面截图、改前改后对比图，不重复转写；只转录文字没覆盖的图（提示词全文、选项弹窗、示例指令）。

## 三、公众号名（写进 `author`）

要的是**账号名**，不是作者笔名：

- 首选：直抓页面 HTML，取 `id="js_name"` 标签内的账号名。
- 对照：`var author = "..."` 是作者笔名，**不要用**。实例：`js_name` = 阿紫与AI产品经理、`var author` = 阿ZI，正确值是前者。
- 正文署名行也可用，规律为「作者 公众号 日期」，或出现在 `公众号：X`、`作者：X（公众号：Y）` 中。
- **短图文帖（`type: '10002'`，一段话 + 链接的「分享」型推送）没有 `id="js_name"`**：改取页面 JS 里的 `nick_name:` 或 `window.name = "..."`。实测：《一句话，画出一张图》的 `js_name` 为空，`nick_name` / `window.name` = 东裕智能GitHubAI雷达。
- 三处都取不到才写 `来源未识别`，且**不得改写成 `Andrew`**（语义是「没抓到来源」，不是「本人原创」）。

## 四、抓取失败

- WebFetch 不完整 → browser_use 子代理导航 → browser_snapshot 取正文，必要时 browser_take_screenshot 截图后 Read。
- 下载图片失败（防盗链）→ 同上，改截图路线。
- 三条路都拿不到正文（登录墙、付费墙、403、链接失效）→ **直接告诉用户抓不到，说明卡在哪一步，不凭标题或摘要猜内容**。已抓到的部分可以交付，但要标注缺了哪些段落或图片。
