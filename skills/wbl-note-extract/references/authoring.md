# 提取与输出适配

> 步骤 5（提取核心价值）与步骤 6（结构化整理）按需加载。

## 一、保留什么

- 值得学习、值得收藏的核心知识点
- 关键操作步骤、参数、配置
- 核心论点、关键数据、结论
- 原始提示词、代码、配置文件（不缩减，原文保留）
- 图片中的关键信息（理解后转成文字）

## 二、去除什么

- 背景铺垫、引入段、故事开头
- 「关注 / 点赞 / 转发」「进群领资料」等推广引导
- 与核心价值无关的个人感悟、闲聊
- 重复表述、过渡句
- 装饰性内容（封面图、分割线、二维码）

## 三、按文章类型适配

**工具 / 经验类**（工具教程、操作指南、经验分享）

- 提取重点：核心步骤、关键参数、注意事项、避坑指南
- 输出方式：编号列表 + 代码块（参数 / 命令）+ 引用块（注意事项）

**SKILL / 提示词类**（AI 提示词、Skill 代码、配置文件）

- 提取重点：原始内容完整保留，附使用说明和关键点解读
- 输出方式：代码块保留原文 + 编号列表说明要点
- 硬原则：原始内容不缩减、不改动

**观点 / 分析类**（行业分析、趋势判断、方法论）

- 提取重点：核心论点、关键数据、推理逻辑、结论
- 输出方式：分条列述 + 引用关键数据 + 结论高亮

**图文并茂类**（图文卡帖等图片为主的内容）

- 提取重点：每张图片的核心信息 + 对应文字说明
- 输出方式：按图片顺序分条总结，图意与文字匹配
- 硬原则：图片信息转成文字描述，不依赖原图即可读懂

**其他类型**

- 按内容本身逻辑结构化呈现，值得收藏的价值点逐条列出

## 四、排版偏好

- 优先用列表与标题分层；**数据对比、参数对照、多方案并列才用表格**，其余不用——表格在窄屏上要左右滑。
- 不使用 emoji 与装饰符号。
- 长文允许长，但不允许平铺：同一层级的内容必须归到一个标题下。

## 五、一次给多个链接

- 每篇各存一个文件，**不合并**。合并会破坏 frontmatter 的单一来源语义。
- 逐篇走完「抓取 → 提取 → 审核 → 自检」，都完成后再统一汇报。
- 其中某篇抓取失败，不影响其余篇目落盘，汇报时单独列出。
