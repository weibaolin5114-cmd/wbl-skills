# 核心内容抓取 (wbl-note-extract)

> 从公开网页/文章中提取核心价值，生成值得收藏的个人笔记。

**定位**：不是摘要工具，而是把一篇长文压成「能直接复用」的要点的提取器。先理解全文，再判断什么值得收藏，最后结构化输出；去掉铺垫、推广和重复，只留核心。

按需加载：微信抓取判据见 `references/wechat-fetch.md`，提取与排版细则见 `references/authoring.md`，历史版本见 `references/changelog.md`。

---

## 一、输入要求

用户提供一个或多个公开链接。按**页面类型**分类，不同类型走不同抓取路径：

- **静态文章页**（正文随 HTML 一次返回）：WebFetch 通常直接拿到 Markdown 正文
- **需渲染的动态页**（正文依赖 JS 或交互才出现）：WebFetch 常不完整，走浏览器渲染回退
- **图文卡帖页**（信息主要承载在系列图片中）：需逐图理解，图文缺一不可

可选输入：

- 补充关注重点（如「只关注工具使用部分」）
- 声明这是本人笔记（如「这是我自己写的」「我自己整理的」）——影响 `author` 取值，见步骤 8

---

## 二、处理流程

### 步骤 1：抓取内容

1. 首选 WebFetch，直接取 Markdown 正文。
2. 不完整时回退：浏览器子代理导航页面 → 取快照文本；仍缺就截图后 Read。
3. 三条路都拿不到正文（登录墙、付费墙、403、链接失效）→ 告诉用户抓不到、卡在哪一步，**不凭标题或摘要猜内容**。拿到一部分就交一部分，并标明缺了哪些段落。

### 步骤 2：识别图片

- **信息型**（含核心内容）→ 需要理解：教程截图、信息图、流程图、代码截图、对比图、参数图、架构图、图文卡帖
- **装饰型**（无核心信息）→ 忽略：头图封面、分割线、表情包、推广 banner、作者头像、页尾二维码

### 步骤 3：理解图片内容

1. 抓页面 HTML，从正文区取图片真实地址并下载，用 Read 读图理解文字与结构。
2. 下载失败（防盗链等）→ 浏览器子代理截图后 Read。
3. 把图片理解结果与对应段落对上，形成完整理解。
4. 微信来源的取址与判定口径（`data-src`、`Referer`、`data-w` 非阈值、占位图识别、逐张读的止损线）全部在 `references/wechat-fetch.md`，直接套用。
5. 笔记里若要嵌图片链接，只能从 HTML 的 `data-src` 原样复制，禁止拼接猜测；写完回读抽查。

### 步骤 4：全文理解

通读文字 + 图片理解结果，判断核心主题、结构与文章类型（类型决定输出方式，见 `references/authoring.md`）。

### 步骤 5：提取核心价值

保留：核心知识点、操作步骤与参数、论点数据结论、原始提示词与代码（不缩减）、图片中的关键信息。

去除：背景铺垫、故事开头、关注点赞转发等引导、无关闲聊、重复表述、装饰性内容。

完整清单与按类型适配的提取重点见 `references/authoring.md`。

### 步骤 6：结构化整理

1. 按逻辑分层排列，逐条呈现，不限长度但必须结构化。
2. **加粗的 `**` 必须紧邻文字，标点放外面**：写 `"**交付可靠**"`、`《**手册**》`、`**工具**（Tool）是`；不写 `**"交付可靠"**`、`**《手册》**`、`**工具（Tool）**是`。markdown-it 按 CommonMark 的 flanking 规则判定，`**` 外侧紧贴标点或内侧首尾带空格时整段不渲染，预览里直接显示 `**`。
3. **列表标记只留一层**：原文 `li` 常自带 `•`、`·`、`1.`，抓取时一并进了正文。写列表剥掉原文符号，只留自己生成的 `- ` 或 `1. `，不出现 `- • 文字`、`1. 1. 文字`。
4. **不写反斜杠转义**：`\*\*` 是 HTML→Markdown 转换器的产物，落盘前还原成 `**`；要原样保留就用行内代码或代码块。
5. 表格只用于数据对比、参数对照、多方案并列，其余用列表——窄屏上表格要左右滑。
6. 不用 emoji 与装饰符号。

### 步骤 7：审核检查

生成最终笔记前必须过一遍，不通过就改完重审。

内容完整性：

- [ ] 核心价值点无遗漏，图片中的关键信息已纳入
- [ ] 原始内容（提示词 / 代码）完整保留，未缩减
- [ ] 删掉的确实属于冗余，没有误删核心内容

格式与字段：

- [ ] 加粗两侧满足 flanking，正文无 `\*\*` 转义残留
- [ ] 列表无双符号（`- • `）与双编号（`1. 1\. `）
- [ ] `tags` 1~3 个内容主题词，无「个人笔记」这类无区分度标签
- [ ] `author` 按步骤 8 分派，**有原文链接的没有写成 `Andrew`**
- [ ] `created` 是本次处理当天，不是原文发布日期
- [ ] 来源链接可点击跳转，结构与内容类型匹配

### 步骤 8：生成笔记

1. **`author` 写来源身份，不是整理人**：
   - 外部文章 → 公众号账号名（不取笔名）。取法见 `references/wechat-fetch.md` 第三节。
   - 书籍、课程、讲座、他人文章的整理笔记 → 原作者或机构（如「宝玉」「厦门大学」），不是自己。
   - 本人原创笔记 → `Andrew`，条件是本轮用户明确说明，且**没有外部原文链接**。
   - **硬约束**：`source` 是原文文章链接（http）时，`author` 不得写 `Andrew`。Andrew 是本人英文名，只代表本人原创，不能替别人署名。例外：`url` 只填产品/工具官网而非原文文章、正文确为自己整理，仍可写 `Andrew`。
   - 三处都取不到 → `来源未识别`。语义是「没抓到来源」，**不是本人原创**，也不能拿它反推成 Andrew。
   - 不得靠 tags 里的「个人」推断作者：标签是内容主题，作者是来源身份。
2. **`created` 写入库日期**，即本篇落到 raw/ 的当天。看板日期轴与「今日新增」只认这个字段。原文发布日期写 `published`，取不到就不写。**禁止把发布日期填进 `created`**：那会让今天入库的笔记挂到几天前，日期轴上入库日整天空白。
3. **`tags` 写 1~3 个内容主题词**，不写「个人笔记」。
4. **来源链接**：`url` 与 `source` 填同一个原文地址（看板按 `url` → `link` → `source` 顺序回落，缺一仍可读），不另造字段。
5. 生成 .md 并按第四节的目录规则落盘。
6. 落盘后跑格式自检，BLOCK 级的先 `--fix` 再交付，WARN 级人工确认。

## 三、笔记输出格式

```markdown
---
title: 文章标题
source: 原文URL
url: 原文URL
author: 公众号名称   # 本人原创写 Andrew；抓不到来源写「来源未识别」
tags: [标签1, 标签2]
created: YYYY-MM-DD   # 入库日期＝本次处理当天
published: YYYY-MM-DD # 可选：原文发布日期，取不到就不写
---

# 笔记标题

> 原文：[原文标题](原文URL)

## 核心要点

1. 核心价值点一
2. 核心价值点二
3. 核心价值点三

## [按内容类型组织的正文]

（结构化内容，逐条呈现）

（关键原始内容如提示词 / 代码，用代码块原样保留）
```

说明：

- 正文开头只留一行可点击的来源链接，不再重复贴纯文本地址。
- 正文结构由内容决定，但必须分层归位；同一层级的内容要归到同一标题下。
- 不在正文末尾加工具署名或生成说明。

---

## 四、输出目录规则

1. 默认保存目录：`E:\08AI\05-个人知识库\raw`。
2. 目录不存在 → 暂停并与用户确认路径，禁止默认写入其他位置。
3. 文件名：`文章标题简称.md`，不加日期前缀，不带「个人笔记」后缀。日期由 `created` 承载。
4. 文件名安全处理：Windows 非法字符 `\ / : * ? " < > |` 换成全角或删除；超过 60 字截断；重名时末尾加 `-2`、`-3` 递增。
5. 用户指定了路径则优先用用户路径。

## 五、格式自检

`scripts/md_normalize.py`：把抓取环节带进来的格式脏数据机械清掉。纯标准库，无依赖。

```
python scripts/md_normalize.py <文件或目录>          # 体检，不写盘
python scripts/md_normalize.py <文件或目录> --fix    # 体检并原地修复
python scripts/md_normalize.py <文件或目录> --quiet  # 只列有问题的文件
```

| 现象 | 落盘时的样子 | 脚本处理后 |
|---|---|---|
| 加粗显示成字面 `**` | `到\*\*"交付可靠"\*\*；` | `到"**交付可靠**"；` |
| 加粗显示成字面 `**` | `是**「终点职级」**（` | `是「**终点职级**」（` |
| 加粗显示成字面 `**` | `**安全问题：**它` | `**安全问题**：它` |
| 列表符号重复 | `- • 文字` / `1. 1\. 文字` | `- 文字` / `1. 文字` |
| 列表标记多余转义 | `1\. 文字` / `\- 文字` | `1. 文字` / `- 文字` |

约定：

- 跳过 YAML frontmatter、代码块与行内代码。
- 加粗可渲染性按 CommonMark 的 flanking 规则判，与看板 markdown-it 实测一致；标点逐个挪到 `**` 外面，不动文字。
- 只处理成对转义。`138\*\*\*1234` 这类奇数组转义星号是正常内容，不动。
- 裸 `• 文字` 行不处理：那是原文自带符号，渲染正常。
- 改不动的报 WARN 交人工：`\*\*` 出现奇数次（丢了半边定界符）、4 个以上连续星号（定界符翻倍）。
- 表格与行内代码里的 `**` 多为 glob 通配符（`src/**/*.py`），检测时排除。
